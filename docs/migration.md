# 移行記録

## 2026-10-19

整理前の走行6ピン復元・カメラ撤去は `b69abdf` に保存し、リモートへpush済みです。
以後の本移行は別の作業差分です。移行作業は実機への書き込み、接続先IP変更、履歴書換えを行いません。

## 適用した境界

- 現行Webアプリの場所は `web-controller` のまま保持。
- 走行＋LCDとカメラ専用スケッチを `firmware` 以下へ分離。
- 既存のモーター／Wi-Fi診断は `firmware/diagnostics` へ移動。
- シリアル診断は `scripts` へ移動し、ポート指定と明示リセットへ変更。
- 旧README／ガイド／Slidev／Vue図ビューア／図／Archifyを `archive/workshop` に一括保管。
- 旧教材のnpm依存とlockfileはアーカイブ側に保持。ルートnpmはFleetの起動・検証入口。
- Hubは物理deviceIdと論理robotIdを分け、カメラ割当と登録済みデバイスを永続化。
- 能力宣言のない走行FWも受け入れ、既存`vehicles`一覧とdrive形式を維持。
- UIは保存結果・重複割当防止・カメラ断警告に対応。割当先カメラへ撮影／配信を送信。
- 走行モード・映像・ルートは再起動復元しない。カメラ断は走行停止に連動しない。

## 適用順序

1. Hub実行PCで既存構成とローカル設定をバックアップします。
2. 新配置へ移行し、`npm --prefix web-controller ci` で依存を再現します。
3. 新Hubを起動します。旧走行FWも接続可能です。初回に保存ファイルが作成されます。
4. 走行機を新FWへ更新する場合は、まずWebSocketモードで単体受け入れを行います。
5. 別基板XIAOへカメラ専用FWを設定し、撮影確認後にFleet上で割り当てます。
6. 実機受け入れ項目は [firmware.md](firmware.md)、保存・シミュレーションは [fleet.md](fleet.md) を参照します。

既存 `esp32_rc_car/wifi_secrets.h` は `firmware/esp32_rc_car/wifi_secrets.h` へ移動します。
別PCではGitに含まれないため、そのPCの設定を手動で新配置へ引き継いでください。
カメラ側は別設定です。Hub実行PCのIPは開発PCと同一とは限りません。

## 切り戻し

運用中は先に全台停止し、Hubを停止します。`fleet.json` をバックアップしてから、
以前の作業ツリー／配布物に切り戻してください。旧Hubは新しい保存ファイルを使用しません。
走行の基本JSONは互換ですが、旧Hub/UIに独立カメラの割当機能はありません。
新しいカメラFWだけを旧Hubへ接続しても、新しい構成編集は利用できません。
実機FWの切り戻しは、以前の既知の正常なバイナリ・ボード設定を使用してください。

## 段階的に残すもの

大規模な表情エンジン・Bluetooth実装の全面分割は、実機受け入れ後に行います。
今回の機能分離に不要なモノレポ化、認証の新設、外部DBへの移行、経路制御の再設計は含めません。
JSON保存は小規模・単一Hub前提です。多重Hub、同時操作者の制御権、デバイス登録認証、
デバイス廃止・交換操作は別の機能追加として設計が必要です。
