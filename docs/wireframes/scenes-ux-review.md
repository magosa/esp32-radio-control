# `/scenes`（シーンエディター）第三者目線 UI/UX 徹底レビュー＆改善提案書

現行の `/scenes` 画面は、視覚的な文字サイズや高密度化によって「見た目の崩れ」こそ解消されたものの、**情報アーキテクチャ（IA：どこに何があるか）** と **インタラクションフロー（どう操作し、どう画面が遷移するか）** の観点では、機能追加のたびにボタンやモーダルをつぎはぎした構造になっており、操作効率・認知負荷ともに深刻なUX上の問題を抱えています。

本レビューでは、HCI / UXデザインの5大基本原則に基づき、現行UIの構造的欠陥を厳しく批評したうえで、それぞれの改善方策をセットで提示します。

---

## 評価の基準とする UX 基本原則

1. **近接の法則・共通領域の法則（ゲシュタルト原則）**  
   同じ対象（プロジェクト／マップ／トラック（行）／アクション（動作））に対する情報と操作は、空間的に1か所にまとまっていなければならない。
2. **フィッツの法則（Fitts's Law：移動距離 $D$ とターゲット幅 $W$）**  
   一連の作業フローにおける視線とマウスの移動距離 $D$ は最小化されなければならない（画面の左端・中央下・右上・右下を往復させてはならない）。
3. **ヒックの法則（Hick's Law：選択肢の数と重複の排除）**  
   同じ意味の操作が複数箇所に重複して存在すると、ユーザーは「どちらを使うべきか」迷い、画面の情報ノイズが倍増する。
4. **直接操作と文脈維持の原則（Direct Manipulation & Non-Modal Context）**  
   キャンバスやタイムラインを見ながら微調整したいパラメータ編集で、画面全体を覆い隠すフルスクリーンモーダル（特に**モーダルの上にさらにモーダルを重ねる二重ポップアップ**）を乱用してはならない。
5. **NLE（Adobe Premiere Pro / DaVinci Resolve）のメンタルモデル**  
   「左＝素材・構成（Bin/Outliner）」「中央上＝モニター（Stage）」「中央下＝タイムライン（トラック追加・編集はタイムライン直結）」「右＝選択中要素のプロパティ（Inspector でその場で数値・座標編集）」という役割分担を守る。

## 洗い出した 7 大 UI/UX 問題点と改善方策

### 問題1：【近接の法則違反】「マップ」に関する情報と操作が画面の4箇所に散乱している
- **課題**：マップ切替・名前変更・削除が上部 `MapTabs`、マップ編集ボタンとグリッド表示が左 `LibraryPanel`、グリッドON/OFFが中央 `MapStage`、扉の確認モードと安全の警告が右下 `Inspector` 最下部に分散している。また非アクティブタブにも常時「名前変更」「削除」が露出してノイジーになっている。
- **改善方策**：非アクティブタブの「名前変更」「削除」ボタンを隠してアクティブタブのみに集約し、扉の確認モードや安全の警告は未選択時（マップ全体設定時）および折りたたみセクションに整理する。

### 問題2：【ヒックの法則・フィッツの法則違反】右上「行と動作を追加」と右下「設定」と「タイムライン」の重複・長距離移動
- **課題**：タイムラインで行を選ぶと、右上 `TrackPalette` と右下 `Inspector` の両方に「動作の追加」「上へ／下へ／行を削除」が二重に出現する。またタイムラインの行を追加するのに画面右上の端までマウスを移動させる必要がある。
- **改善方策**：タイムラインのヘッダーバーおよび左パネルからも直感的に行を追加できるようにし、右パネル内の重複ボタンを排除して右下のインスペクタ領域を広く確保する。

### 問題3：【重複と役割曖昧】左パネル「ライブラリ」がタイムラインの劣化コピーになっている
- **課題**：左パネルの「シーン内のオブジェクト」に名前と種別しか出ず、追加ボタンもないため「右のパネルから追加します」と反対側へ誘導している。
- **改善方策**：左パネルの「シーン内のオブジェクト」セクションにクイック追加ボタン（`＋ロボ` `＋人` `＋部屋` `＋表示`）と各オブジェクトの要約（初期位置・動作件数・ロボットID）を表示し、アウトライナーとして機能させる。

### 問題4：【多重モーダル地獄】「シーケンス一括設定 / 動作編集」→「座標ピッカー」の二重フルスクリーンポップアップ遷移
- **課題**：
  1. タイムラインの動作バーを選択しても、右パネル `Inspector` には「状態」しか表示されず、名前・開始秒・長さ・座標・テキストを1つもインライン編集できない。
  2. `ActionDialog` / `SequenceDialog` の右半分に大きなマッププレビュー（`PreviewPane`）があるのにクリックできず、わざわざ「マップで指定」を押して2重目のモーダル（`CoordinatePicker`）を開かされる。
- **改善方策**：
  1. 右パネル `Inspector` の `ActionPanel` に **インライン直接編集フォーム（動作名・開始秒・実行秒・移動先座標・表示テキスト等）** を実装し、モーダルを開かずにその場で編集可能にする。
  2. `ActionDialog` / `SequenceDialog` 内の `PreviewPane` のマップを **直接クリックして移動先座標や部屋を指定できる** ようにし、二重モーダルを開かずに完結させる。

### 問題5：【上部バーの階層過多】プロジェクトバーとマップタブバーの視覚的整理
- **課題**：編集系（元に戻す・やり直し・編集履歴）とファイル入出力系（新規・JSON保存・JSON読込）が区切りなく混在し、縦スペースも圧迫している。
- **改善方策**：編集系グループとファイル系グループをセパレータで明確に分け、プロジェクトバーとマップタブバーの余白・高さをさらに引き締める。

### 問題6：【ステージヘッダーの文脈混在】「マップ表示設定」と「外部画面送出（展示・実機実行）」の混在
- **課題**：ビューポート表示設定（パス・グリッド・ズーム）と外部出力（展示・実行画面）が同じトーンで並び、展示パネル展開時にプレビュー再生バーと紛らわしい。
- **改善方策**：ステージヘッダー右側の外部出力群をセパレータで分離し、展示コントロール展開時に「50インチ展示モニター送出」であることを明示する。

### 問題7：【操作フィードバックの分散】エラー・警告・通知の分散とジャンプ機能不足
- **課題**：警告リストが複数箇所にただのテキストとして出るだけで、どの時刻・どのバーの問題か追えない。
- **改善方策**：警告・エラー項目をクリックすると、該当時刻へ再生ヘッドをシークして対象箇所を即座に確認できるようにする。
